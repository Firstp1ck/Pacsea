Architecture and trust flow

Fail-closed identity

Queue, results, acknowledgements, restart projection, and continuation are keyed to exact (package_base, commit_oid). Mutable sources and AUR HEAD are rechecked.

Constrained optional process

Pi receives no shell, write, network, built-in, ambient extension, skill, prompt-template, context-file, or theme authority.

Bounded wall clock

The observation cycle carries one 90-second budget through AUR RPC DNS, headers, streamed bodies, redirects, and sequential Git operations.

Key completed controls

Consent

Exact Pi version, selected route, advertised models, worst-case token/micro-USD reservation, pricing provenance, thinking level, and tool contract are displayed before consent. Material drift resets consent even when runtime toggles were off.

Dry-run

Performs realistic bounded observation/acquisition, but never resolves or launches Pi, publishes snapshot roots, or reads/writes durable scanner state.

Recovery

Corrupt/newer state quarantines fail closed. Interrupted targets retain their full frozen identity, reservation, and retry path. Shutdown is distinguished from user cancellation.

Service behavior

Exactly one transient-only pre-model retry is shared across RPC and acquisition. Systemic failure stops draining and applies a sticky pause; production clears it only after target-specific setup and acquisition revalidation.

Storage

Private atomic create_new writes, semantic reload validation, bounded retention, independent baseline and consent documents, and no raw prompt/source/thinking/response persistence.

Network and signatures

Public HTTPS only, explicit credential-free proxy only, NAT64/private ranges denied, exact fingerprint retrieval, isolated GnuPG home, and exact import/signature fingerprint binding.

Review history and dispositions

Independent reviews were deliberately rerun after each material finding set. Accepted findings drove fixes for restart projection, consent binding and informed display, fallback gating, manual observation, transient retry/service pauses, duplicate candidates, whole-cycle deadlines, dry-run production routing, shutdown status, retention, NAT64 policy, and atomic writes.

Final accepted residual risks
  • A compromised host Pi binary remains an explicitly accepted optional-dependency boundary.
  • Prompt injection and model false negatives remain possible; deterministic controls and advisory-only semantics limit authority.
  • Dry-run performs disclosed read-only network acquisition.
  • Real paid provider calls and arbitrary live hostile repositories were not part of normal tests.
Intentional deviations recorded

Pricing and signing-key caching were implemented conservatively or deferred where fresh re-probing/fetching is safer. No README or wiki files were changed under project policy.

Operational next steps

  1. Keep pi_scan_enabled = false by default and require the Setup verification/consent flow before use.
  2. Review exact route pricing and provider privacy before enabling paid execution or ordered fallback.
  3. Treat every result as advisory. A “Complete” result means only “no findings in analyzed scope,” never safe, trusted, or approved.
  4. Use the standard CI sequence on future scanner changes and rerun live no-model probes when Pi versions change.
